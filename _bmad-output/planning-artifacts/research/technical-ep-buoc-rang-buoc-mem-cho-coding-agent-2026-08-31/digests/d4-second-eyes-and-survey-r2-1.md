# D4 · Second pair of eyes, and the survey that settles D3's contradiction — round 2

Budget spent: 11 tool calls. Returned 2026-08-31.

## Task A — the TACL survey resolves the Huang/Self-Refine contradiction

**The survey's headline claim, quoted:** *"no prior work shows successful self-correction of responses
from LLMs using feedback generated by prompting themselves under fair settings in general tasks."*
Negative results across arithmetic reasoning, closed-book QA, code generation and plan generation. The
identified bottleneck: "generating reliable feedback on their own responses is still observed to be
challenging."
Source: Kamoi et al., "When Can LLMs Actually Correct Their Own Mistakes? A Critical Survey of
Self-Correction of LLMs", [arXiv:2406.01297v3](https://arxiv.org/html/2406.01297v3) /
[TACL, MIT Press](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00713/125177/), 2024.
Accessed 2026-08-31. Confidence: **high** — primary survey, directly fetched.

**The resolution is methodological, not "both right in different regimes".** The survey diagnoses *why*
Self-Refine and its kin report gains:

- **Self-Refine** "uses instructions or few-shot examples that do not correctly correspond to the target
  task **only for initial response generation**", while using correct instructions for the correction
  step. The "before" baseline is deliberately weakened, which inflates the apparent gain.
- **RCI Prompting** uses ground-truth answers to decide *when* to apply correction.
- **Reflexion** uses exact-match against ground truth to generate its "feedback".

All three leak an oracle into a setup described as feedback-free. So D3's contradiction was not two
valid findings in tension — one side was measuring something other than intrinsic self-correction.

**Where self-correction genuinely does work**, per the survey's taxonomy:

| Condition | Works? |
|---|---|
| Task whose **verification is much easier than the task itself** (decomposable responses; CoVe cited) | Yes, intrinsic |
| A reliable **external tool or oracle** exists (e.g. a code interpreter) | Yes, external-feedback |
| Large training data available for a feedback generator | Yes, fine-tuned |

The survey frames **reliability of feedback generation** as the single variable determining success
across all three categories.

No new accuracy-delta table surfaced — the contribution is taxonomy and methodological critique, not a
leaderboard.

## Task B — does a fresh session catch what the same session misses?

**One controlled study found, and it points the right way but weakly.**
"Cross-Context Review: Improving LLM Output Quality by Separating Production and Review Sessions",
Tae-Eun Song, [arXiv:2603.12123](https://arxiv.org/abs/2603.12123), 2026-03-12. Accessed 2026-08-31.

30 artifacts (code, technical documents, presentation scripts), 150 injected errors, 4 conditions,
360 reviews:

| Condition | F1 | vs. CCR |
|---|---|---|
| **CCR** — fresh session, no access to production history | **28.6%** | — |
| SR — same-session self-review | 24.6% | p=0.008, d=0.52 |
| SA — context-aware subagent review | 23.8% | p=0.004, d=0.57 |
| SR2 — same-session self-review, twice | 21.7% | p<0.001, d=0.72 |

Stated key finding: *"reviewing twice in the same session did not beat reviewing once (p=0.11), which
rules out repetition as an explanation for CCR's advantage. The benefit comes from context separation
itself."*

Confidence: **medium-low** — single-author arXiv preprint, not confirmed peer-reviewed. And the
absolute numbers matter as much as the ranking: **even the best condition misses roughly 70% of
injected errors.** Context separation is a real but modest improvement, not a solution.

**Human code review, for comparison — unverified figures.** Search synthesis surfaced the classic SE
numbers: inspection defect-detection ~55–60% (Shull et al. lineage); one Aetna case 82%; an IBM case
82% of defects found for a released product; unit testing alone ~25%, function testing ~35%,
integration ~45%. Confidence: **low-medium** — search synthesis citing them, primary papers not
fetched.

**Production practice: descriptions, no numbers.** MindStudio "Verifier Pattern", Augment Code
"Adversarial Code Review", CodeRabbit, and a "Conduct" pre-execution review agent all describe shipping
a separate reviewer with no inherited context as a blocking gate, claiming qualitatively that it
"catches what the first agent missed" — **none published a measured detection rate.** Confidence: low,
marketing register.

**Cross-model disagreement as a signal — weak in the one dataset found.** Search-snippet evidence
(unfetched) reports that in a bug-triage dataset, AI convergence had minimal relationship to fix
acceptance: 34.1% acceptance for high-convergence cases vs 31.7% otherwise — a 2.4-point difference.
Confidence: low, unverified.

## Contradictions

- **Round 1's framing was wrong.** Huang and Madaan do not disagree about results; per the survey they
  disagree about evaluation validity, and Self-Refine's setup leaks an advantage into the correction
  step. This is a stronger and less comfortable resolution than "both are right in different regimes"
  — though the survey does carve out one genuine regime (tasks whose verification is easier than the
  task).
- **Vendor narrative vs. the one measurement.** Blogs present a separate reviewer agent as an obvious
  win; the only controlled study found puts fresh-context review at F1 28.6% — better than same-context
  self-review, and still missing most injected errors.
